# Objects Manager and Connections Manager

All ✅ items were executed over REST on UAT 2026-09-21 against `maher_scratch_task` and
connection `6ab0ea7a5459f4370f0c1f3f`.

## Objects (Data Objects)

An object is an **`EntityType`** (aggregation group `STANDARD`). Its id is either what you pass
(`maher_scratch_task`) or generated (`obj_<5 chars>` for agent-created ones); `name`/`lcName` are the
display names. Its records are entities whose `entityType` is the object id. ~18,300 custom
objects on UAT.

### Endpoints

| Step | Call | |
|---|---|---|
| Create | `POST /api/entity-type` `{id, name, pluralName, description, metadata:{storeDetails:{store:"MONGO"}}, tags:[]}` | ✅ |
| Read one | `GET /api/entity-type?entityType={id}` | ✅ |
| Read many | `POST /api/lookup?ByKeys=ENTITY_TYPE` `{type:"ByKeys", lookupType:"ENTITY_TYPE", keys:[ids]}` | ✅ |
| Update schema / settings | `POST /api/entity-type/update` — the **full** object as read, with `input` and `schema` set | ✅ |
| List objects | `POST /api/aggregation?entityType=EntityType&group=STANDARD` (filter `standard` false/MISSING for custom; project `name,id,columns,tags,oUId,cTm,mTm`) | ✅ |
| Field metadata | `POST /api/lookup?ByQuery=ENTITY_FIELD` `{options:{group:"ENTITY", entityType}}` or `POST /api/aggregation/metadata?entityType={id}&group=ENTITY` | ✅ |
| Permissions | `POST /api/lookup?ByKeys=ENTITY_PERMISSIONS` `{options:{entityType:"ENTITY_TYPE"}, keys:[id]}` | 👁 |
| Import history | `POST /api/entity/e_file_import_details` filter `properties.entityType` | 👁 |

Dead ends: `GET /api/entity-type/{id}` 404, `/api/entity-type/find/{id}` 404,
`/api/entity-type?id=` 500, `lookup?ByKeys=EntityType` 5004 (*Lookup type not supported*).

UI store types on create: JSON Store (`MONGO`), Blob Store, Key Value Store, Event Store, Vector
Store, Analytics Store; plus Retention period, Workspace, Tags, and toggles Enable reporting /
activity tracking / audit trail / external access. Only `MONGO` has been exercised.

### Schema format

`input` and `schema` carry the same JSON Schema:

```json
"input":  {"type":"SCHEMA_AND_LAYOUT", "schema": <S>, "layout": {"ui:order": ["task_code","title",...]}},
"schema": {"dynamic": false, "type": "SCHEMA", "schema": <S>}

<S> = {"type":"object", "additionalProperties": false, "required": ["task_code","title"],
       "properties": {
  "task_code":      {"type":"string","title":"Task Code","help":"Business key","primaryKey":true,"nameField":true,"uniqueKey":false,"searchable":true,"sortable":true,"filterable":true},
  "title":          {"type":"string","format":"text","title":"Title"},
  "status":         {"type":"string","format":"single-select","default":"open","oneOf":[{"const":"open","title":"Open"},{"const":"done","title":"Done"}]},
  "estimate_hours": {"type":"number","title":"Estimate (h)"},
  "is_blocked":     {"type":"boolean","title":"Blocked?"},
  "due_at":         {"type":"integer","format":"date-time","dateFormat":"epoch","title":"Due At"},
  "email":          {"type":"string","format":"email"},
  "task_no":        {"type":"string","format":"auto-generate","autoGeneratedFieldDefinition":{"prefix":"TSK-","startFrom":1001},"primaryKey":true,"uniqueKey":true},
  "category":       {"type":"string","format":"single-select","foreignKey":{"reference":"ENTITY_ID:<targetObjectId>"}}
}}
```

- UI field types: String, Number, Integer, Auto Number, Boolean, Date, Date Time, Single/Multi
  Select Dropdown (static `oneOf` or a Lookup `foreignKey`), Object, Array, File; Vector/Geo Point
  for vector stores. Advanced: hashing, secure (encrypted) field, display name, search/sort/filter, visibility conditions.
- The server **derives `metadata`** from the per-field flags on save: `primaryKeyField`,
  `nameField`, `uniqueKeyFields`, `searchableFields`, `filterableFields`, `dateFields`,
  `autoGeneratedFields`, `referenceKeys` (from `foreignKey`). You set flags, not metadata.
- A lookup field stores the target record's `id` (array of ids for multi-select). Foreign keys
  are only checked if enforced; nothing cascades.

### Records

| Step | Call | |
|---|---|---|
| Create | `POST /api/entity` `{entityType:<objectId>, properties:{...}}` — the record `id` = the primary-key value | ✅ |
| Read | `GET /api/entity/{objectId}/{recordId}` | ✅ |
| List/filter | `POST /api/entity/{objectId}` `{filter:{op:"EQUAL", field:"properties.status", values:["done"]}, sorts:[{field:"cTm",order:"DESC"}], page:{limit,offset}}` (`GT`, `IN`, `AND`/`OR` work) | ✅ |
| Aggregate | `POST /api/aggregation?entityType={objectId}&group=ENTITY` with `projections:[{name:"properties_title"}]`, filter field `properties_status` | ✅ |
| Update | `POST /api/entity/update` `{id, entityType, version, properties:<FULL record>}` | ✅ |
| Delete | not over REST (`405`) — use `storage_by_unifyapps_delete_record(s)` in a workflow or a DELETE data source | — |

Validation errors (all `500`, `rootCauseMessage` starts `Non Empty Validations in Validating entity <obj> with validationResult …`):
`property status invalid; oneOf fail` · `required title` · `add additionalProperties nope` ·
partial update → `required task_code`. Duplicate primary key → Mongo `E11000 duplicate key … CUSTOMER_ENTITY_<tenant>.<obj>`.

## Connections

~7,830 on UAT. A connection is an authenticated instance of an app (connector).

| Step | Call | |
|---|---|---|
| Connector auth form | `GET /api/applications/{appName}?fields=authSpec,iconUrl,displayName,name,refreshable,includeOptions` → `authSpec.input` (JSON Schema + layout) | ✅ |
| Auth types for an app | `POST /api/lookup?ByQuery=CUSTOMER_AUTH` `{options:{appName, auths:[...]}}` | 👁 |
| Test before saving | `POST /api/connection/input/test?appName={appName}` → **204** on success | ✅ |
| Create | `POST /api/connection/input?appName={appName}` → connection object with `id` | ✅ |
| **Find (fast, server-side)** | `POST /api/aggregation?entityType=Connection&group=STANDARD` `{filter:{op:"AND",values:[{field:"appName",op:"EQUAL",values:["github"]},{field:"active",op:"EQUAL",values:[true]}]}, projections:[{name:"id"},{name:"name"},{name:"appName"},{name:"oUId"}], page:{limit,offset}}` — ~50 ms, no secrets returned | ✅ |
| Read one | `GET /api/connection/{id}` (⚠️ includes `userInput` secrets in clear) | ✅ (earlier) |
| Sharing | `POST /api/lookup/bulk` with `ROLE_MAPPING` `{scopeType:"CONNECTION", scopeId}` | 👁 |

Create/test body (Custom HTTP Application, no auth):

```json
{ "name": "maher_scratch_http (Claude API learning)", "authType": "CUSTOM",
  "inputs": { "name": "...", "requestType": "HTTP", "authType": "CUSTOM",
              "baseUrl": "https://jsonplaceholder.typicode.com", "headersList": [],
              "sslVerify": true, "requestTimeoutInSecs": -1, "connectionType": "DIRECT", "tags": [],
              "rateLimitConfig": {"enabled": false}, "circuitBreakerConfig": {"enabled": false} },
  "options": { "rateLimitConfig": {"enabled": false}, "circuitBreakerConfig": {"enabled": false} },
  "tags": [] }
```

`inputs` follows the app's `authSpec` (e.g. Basic Auth adds username/password; `connectionType`
`DIRECT` or via an On-Prem Agent `groupId`). **OAuth connections (GitHub, Google, Slack…) need
the user to click Authorize** — find them afterwards with the aggregation call and pass the id.
Custom HTTP auth types: CUSTOM, BASIC_AUTH, OAUTH. The New Connection catalogue lists 1,156 apps.
